# Conceptos Clave

 Comencemos este viaje por repasar rápidamente unos conceptos clave, antes de iniciar a identificar los lineamientos y estrategias que debemos tener presente en el momento de trabajar bajo el modelo Open Source.

### Open Source 👨‍💻 

Open Source conocido como código o software abierto, diseñado para ser accedido de manera publica, para ver, modificar, y utilizar. Este modelo de trabajo se enfoca en que equipos, o personas individuales de desarrollo aporten en un proyecto, compartiendo código, conocimientos entre ellos y que sea utilizado por la comunidad en general.

### Repositorio 💾 

En el contexto del desarrollo de software, un repositorio se refiere a un espacio de almacenamiento donde se guarda y gestiona el código fuente de un proyecto. Es un lugar centralizado donde los desarrolladores pueden colaborar, compartir y controlar las versiones del código.

Los repositorios son fundamentales para el trabajo en equipo y la colaboración en proyectos de software. Permiten a múltiples desarrolladores trabajar en el mismo código de manera simultánea y realizar cambios de manera independiente. Estos cambios se guardan en el repositorio en forma de "commits", que representan el registro de las modificaciones realizadas.

Existen sistemas de control de versiones (Version Control Systems, VCS) que se utilizan para gestionar los repositorios de código. Algunos ejemplos populares de sistemas de control de versiones son Git, Subversion (SVN) y Mercurial.

Los repositorios permiten a los desarrolladores proponer cambios, realizar revisiones, colaborar en nuevas características y solucionar problemas, lo que impulsa el desarrollo colaborativo y la mejora continua del software.

### Commit 📥 

En el contexto del modelo de desarrollo de software conocido como "Open Source", un "commit" se refiere a un registro de cambios realizado en el repositorio de código fuente de un proyecto. Un commit es una operación que permite guardar las modificaciones realizadas en uno o varios archivos dentro del sistema de control de versiones utilizado por el proyecto.

Cuando un desarrollador trabaja en una nueva funcionalidad o corrige errores en el código fuente, realiza cambios en los archivos correspondientes. Una vez que está satisfecho con esos cambios, crea un "commit" para guardar los cambios en el repositorio. Cada commit se asocia con un mensaje que describe de manera concisa qué cambios se realizaron en el código.

Los commits son esenciales en el desarrollo colaborativo, ya que permiten rastrear y documentar el historial de cambios realizados en el proyecto a lo largo del tiempo. Los equipos de desarrollo pueden revisar los commits para comprender cómo ha evolucionado el código, facilitando la colaboración y la detección de errores.


### Pull Request 📤 

Un Pull Request o solicitud de extracción, es una forma en la que los desarrolladores pueden colaborar en un proyecto utilizando el modelo Open Source. Cuando un desarrollador hace cambios en el código fuente de un proyecto, puede enviar una solicitud de extracción al equipo encargado de revisar y aprobar los cambios. Esta solicitud de extracción incluye una descripción de los cambios realizados y por qué se realizaron, así como cualquier otra información relevante. El equipo de revisión puede entonces examinar los cambios y decidir si se deben incorporar al proyecto principal.

El modelo de Pull Request es una práctica muy común en proyectos de código abierto, pero también es muy útil en proyectos Open Source, ya que permite a los equipos trabajar de manera colaborativa y asegurarse de que los cambios realizados sean adecuados antes de incorporarlos al proyecto principal.

### Issues 🎏 

En el ámbito de la gestión de proyectos colaborativos, un Issue es una herramienta fundamental para la gestión de proyectos Open Source. Puede ser una tarea pendiente, un error reportado, una vulnerabilidad detectada o una solicitud de mejora que requiera atención o discusión por parte del equipo.

Los Issues en GitHub actúan como un punto central de comunicación y colaboración, permitiendo:

* **Seguimiento de tareas y errores**: Registrar y asignar tareas o errores a miembros específicos del equipo, facilitando la organización y el seguimiento del progreso.
* **Discusión y colaboración**: Fomentar la discusión abierta sobre ideas, propuestas y soluciones, promoviendo la colaboración entre los miembros del equipo.
* **Documentación y transparencia**: Mantener un registro histórico de las decisiones, discusiones y cambios realizados en el proyecto, mejorando la transparencia y facilitando la incorporación de nuevos miembros al equipo.
